## Step 3: Create the SQLite database

Open a SQLite database manager, create `RetailDW.db` inside your project folder, and open its SQL editor.

Execute the following SQL to create the four dimension tables and the fact table.

```
CREATE TABLE Dim_Product (
    Product_ID INTEGER PRIMARY KEY AUTOINCREMENT,
    Product TEXT,
    Category TEXT,
    UNIQUE(Product, Category)
);

CREATE TABLE Dim_Customer (
    Customer_ID INTEGER PRIMARY KEY AUTOINCREMENT,
    Customer_Name TEXT UNIQUE
);

CREATE TABLE Dim_City (
    City_ID INTEGER PRIMARY KEY AUTOINCREMENT,
    City_Name TEXT UNIQUE
);

CREATE TABLE Dim_Date (
    Date_ID INTEGER PRIMARY KEY,
    Full_Date TEXT,
    Day INTEGER,
    Month INTEGER,
    Quarter INTEGER,
    Year INTEGER
);

CREATE TABLE Fact_Sales (
    Sale_ID INTEGER PRIMARY KEY,
    Product_ID INTEGER,
    Customer_ID INTEGER,
    City_ID INTEGER,
    Date_ID INTEGER,
    Quantity INTEGER,
    Price REAL,
    Sales_Amount REAL,
    FOREIGN KEY(Product_ID) REFERENCES Dim_Product(Product_ID),
    FOREIGN KEY(Customer_ID) REFERENCES Dim_Customer(Customer_ID),
    FOREIGN KEY(City_ID) REFERENCES Dim_City(City_ID),
    FOREIGN KEY(Date_ID) REFERENCES Dim_Date(Date_ID)
);
```

What these tables mean

- `Dim_Product`: product names and categories.
- `Dim_Customer`: customer names.
- `Dim_City`: city names.
- `Dim_Date`: date details such as day, month, quarter, and year.
- `Fact_Sales`: the sales transactions and foreign keys linking them to the dimensions.

This is the star schema used to build the sales data mart.

## Step 5: Create the first pipeline — `Load_Dim_Product.hpl`

Create a new pipeline and save it in your project folder.

The pipeline should look like this:

Text File Input

Select Values

Sort Rows

Unique Rows

Table Output

### 5.1 Add Text File Input

1. Click an empty area of the canvas.
2. Search for `Text File Input`.
3. Add the transform and double-click it.
4. In the File tab, browse to `sales.csv` and add it to the selected files list.
5. In the Content tab, set the separator to a comma.
6. Enable the header option and set the number of header lines to `1`.
7. Open the Fields tab and click Get Fields.
8. Preview the records to check that the columns are read correctly.
9. Click OK.

### 5.2 Add Select Values

1. Add a `Select Values` transform.
2. Connect `Text File Input` to `Select Values` by creating a hop.
3. Open `Select Values`.
4. In the Select & Alter tab, retain only `Product` and `Category`.
5. Save the transform.

### 5.3 Add Sort Rows

1. Add `Sort Rows`.
2. Connect it after `Select Values`.
3. Configure the sort fields as:
   - `Product` — ascending.
   - `Category` — ascending.
4. Save.

Sorting ensures identical product-category combinations are adjacent.

### 5.4 Add Unique Rows

1. Add `Unique Rows`.
2. Connect it after `Sort Rows`.
3. Configure the comparison fields as `Product` and `Category`.
4. Save.

This removes duplicate product-category combinations from the stream.

### 5.5 Add Table Output

1. Add `Table Output`.
2. Connect it after `Unique Rows`.
3. Open the transform.
4. Set Connection to `RetailDW`.
5. Set Target table to `Dim_Product`.
6. Enable the option to specify database fields.
7. Click Get Fields and verify that `Product` and `Category` map to their matching columns.
8. Leave `Product_ID` unmapped because SQLite generates it automatically.
9. Click OK.

### 5.6 Run and verify the pipeline

Click the Run button and confirm that all transforms finish successfully.

Execute this query in the SQLite SQL editor:

```
SELECT * FROM Dim_Product;
```

You should see four distinct products: Laptop, Mobile, Headphones, and Keyboard.

## Step 8: Create the date dimension pipeline

Save a new pipeline as `Load_Dim_Date.hpl`.

The purpose is to store each transaction date once, along with its day, month, quarter, and year.

### 8.1 Add the input and remove unnecessary fields

1. Add `Text File Input` and configure it to read `sales.csv`.
2. Add `Select Values` and retain only the `Date` field.
3. Add `Sort Rows`, sorting by `Date`.
4. Add `Unique Rows`, comparing `Date`.

### 8.2 Calculate the date fields

Add the appropriate date-calculation transforms available in your Hop version. You need these output fields:

| Output field | Calculation                                        |
| ------------ | -------------------------------------------------- |
| `Full_Date`  | Source date in `YYYY-MM-DD` format                 |
| `Day`        | Day of the month                                   |
| `Month`      | Month number, 1–12                                 |
| `Quarter`    | `((Month - 1) // 3) + 1`                           |
| `Year`       | Four-digit year                                    |
| `Date_ID`    | Date formatted as `YYYYMMDD`, stored as an integer |

For example, the source date `2026-02-12` should produce:

| Field     | Value      |
| --------- | ---------- |
| Date_ID   | 20260212   |
| Full_Date | 2026-02-12 |
| Day       | 12         |
| Month     | 2          |
| Quarter   | 1          |
| Year      | 2026       |

Use date extraction and formatting transforms to create these fields. If your Hop version provides a Calculator transform with date functions, use it to extract the day, month, and year, and derive the quarter from the month.

### 8.3 Load the date dimension

1. Add `Table Output`.
2. Select connection `RetailDW`.
3. Select target table `Dim_Date`.
4. Map all six output fields to their corresponding database columns.
5. Run the pipeline.

Verify the result:

```
SELECT * FROM Dim_Date;
```

You should get one row per distinct transaction date.

Important: `Date_ID` must match the same `YYYYMMDD` representation used by the fact pipeline. If the ID format differs, the date lookup will fail.

## Step 11: Construct and understand the data cube

A data cube is a multidimensional view of the sales data. In this practical, you can analyze sales using these dimensions:

- Product: Which books or products were sold? In this retail example, products are laptops, mobiles, headphones, and keyboards.
- Customer: Who purchased the products?
- City: Where were the sales made?
- Date: When did the sales happen?

The measures are `Quantity`, `Price`, and `Sales_Amount`.

The fact table and dimensions provide the structure for OLAP analysis. You do not need to create a separate physical cube for the SQL-based OLAP operations in this assignment.

## Step 12: Execute the four OLAP SQL queries

Open your SQLite database's SQL editor and execute each query separately.

### Query 1: Slice — sales for Electronics

Slice selects a single value from one dimension.

```
SELECT p.Category, SUM(f.Sales_Amount) AS Total_Sales
FROM Fact_Sales f
JOIN Dim_Product p ON f.Product_ID = p.Product_ID
WHERE p.Category = 'Electronics'
GROUP BY p.Category;
```

Expected result: One row showing the total sales revenue for Electronics.

### Query 2: Dice — sales for Electronics in Pune

Dice filters on multiple conditions across dimensions.

```
SELECT p.Product, c.City_Name,
       SUM(f.Sales_Amount) AS Total_Sales
FROM Fact_Sales f
JOIN Dim_Product p ON f.Product_ID = p.Product_ID
JOIN Dim_City c ON f.City_ID = c.City_ID
WHERE p.Category = 'Electronics'
  AND c.City_Name = 'Pune'
GROUP BY p.Product, c.City_Name;
```

Expected result: Product-wise sales for Electronics sold in Pune.

### Query 3: Drill-down — sales by year, month and day

Drill-down moves from summarized information to greater detail.

```
SELECT d.Year, d.Month, d.Day,
       SUM(f.Sales_Amount) AS Total_Sales
FROM Fact_Sales f
JOIN Dim_Date d ON f.Date_ID = d.Date_ID
GROUP BY d.Year, d.Month, d.Day
ORDER BY d.Year, d.Month, d.Day;
```

Expected result: Daily sales totals, grouped by year, month, and day.

### Query 4: Roll-up — total sales by year

Roll-up aggregates detailed data into a higher-level summary.

```
SELECT d.Year, SUM(f.Sales_Amount) AS Total_Sales
FROM Fact_Sales f
JOIN Dim_Date d ON f.Date_ID = d.Date_ID
GROUP BY d.Year
ORDER BY d.Year;
```

Expected result: One row per year showing total sales revenue.

## Step 14: Common errors and their solutions

| Problem                               | What to check                                                                             |
| ------------------------------------- | ----------------------------------------------------------------------------------------- |
| Database connection fails             | Verify the SQLite file path and connection settings.                                      |
| CSV fields are read incorrectly       | Check that the separator is a comma and the header row is enabled.                        |
| Duplicate dimension rows              | Ensure `Sort Rows` comes before `Unique Rows`.                                            |
| Missing dimension IDs                 | Run the dimension pipelines before the fact pipeline.                                     |
| Date lookup fails                     | Ensure `Date_ID` uses the same `YYYYMMDD` format in both tables.                          |
| Table Output fails                    | Verify the target table name, field mappings, and data types.                             |
| Fact table contains duplicate records | Check whether the fact pipeline was run multiple times without clearing existing records. |
